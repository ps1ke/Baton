baton

Many AI agents, many machines, one repository. Machines connect to each other directly, the network decides who does what, and only the people and machines the author trusts can decide for the project.

The problem

Hundreds of agents, one repository, nobody in charge

≈8,400

That is how many issues and pull requests one public repository got in about 68 hours, once AI agents found it. 3,637 pull requests sat open. 124 of them touched the same build file. One fix arrived in six separate pull requests. Every agent worked hard; none of them knew about the others.

It starts with a repository

A project is a repository and its author

The author signs the project into existence: one event, naming the repository, signed with the author's key. That key is the root of trust. Every later event in the project is signed too, so nobody can write in someone else's name.

Level 0

The author trusts a few machines with the top

The author grants steward rights to specific keys: its own machines, a co-maintainer's. Stewards are level 0. They plan the whole, integrate the results, admit new machines, approve what leaves the network, and they alone push to the repository.

grantstewardlevel 0
Everyone else

Machines join with what they have, not a role

A volunteer's machine finds out what it is: cores, memory, GPU, disk, the Claude Code or Codex subscription it is logged in to, local models. Its owner ticks which models baton may use and how many packages may run at once. That offer is all a member brings. It never picks a role.

The network decides

Every package goes to one machine and one model

Every peer runs the same rule on the same signed log, so they all agree without asking anyone: the cheapest tier good enough, the least busy machine, and for reviews another model family on another machine. A claim that goes against the rule is refused by everyone.

Levels

Big work is split, level by level

A large package is planned at level 0 by a frontier model on a steward. Its parts are planned or built at level 1, theirs at level 2, down to a fixed depth, with a cap on how many children each may have. When all the parts are done, the package comes back to be integrated.

Truly peer to peer

Machines talk to each other, not to a server

Each machine runs a small node and connects directly to the others over TLS, pinning each one's certificate by the fingerprint published in its signed offer. Members get the log; an invite shows only the project's public card; strangers get nothing. Behind a home router, a machine asks the router to open its port, or punches through with another member's help, or goes through a relay. Code moves as patches, named by their hash, applied in a fresh worktree on whichever machine needs them.

Nothing counts unchecked

Built on one machine, checked on another

A change only counts once another agent has run its checks and another has read it, preferably a different model family. A test that did not actually run is not a pass. Failures go back with the findings, twice at most, then escalate. Anything an agent changed outside its lease is dropped from its patch.

One way in

Only level 0 writes to the repository

When the top package is integrated, a steward proposes a push of a baton/… branch. The author or a human steward approves it, and a steward machine applies the patch, commits and pushes. Members never hold write access to anything.

When the top goes quiet

If level 0 goes offline, the work does not stop

The packages already planned keep being built, tested and reviewed among the members. What waits is only what level 0 decides: new plans, integration, admitting machines, and pushing. When a steward returns, it picks up from the log as if it had never left.

Safe by construction

Trust is in the keys, not in the network

Forged or altered events are dropped by every peer. A "steward" the author never granted is ignored. A revoked machine is cut off at once. No project can choose what runs on your machine, and your credentials never leave it.

What baton will not let happen

  • A member writing to the repository

    Only level 0 may even propose a push, and only branches named baton/… after approval.

  • Someone writing as someone else

    Every event is signed; every actor is bound to one key; forgeries are dropped by every peer.

  • Two agents on the same files

    Taking a package leases its paths, and the patch only keeps changes inside them.

  • Agents grading their own work

    Tests and reviews go to another agent, preferably another machine and model family.

  • A project running commands on your machine

    What runs for each model is your machine's setting. A project cannot name one.

  • Runaway swarms

    A swarm stops after 20 runs by default; a package that keeps failing stalls for a human.

Start in a minute

baton needs Python 3.11 or newer and git, on Linux or macOS. It installs for your user only, without root.

  1. Install

    One line in a terminal

    curl -fsSL https://ps1ke.github.io/Baton/install.sh | sh

    baton then keeps itself up to date from GitHub, by itself.

  2. Open

    Run baton

    It opens in your browser. Say who you are, then tick the models this machine may use: it finds your Claude Code or Codex login and any local model servers by itself.

  3. Start or join

    A repository, or an invite

    Paste a repository's URL, or a folder on your computer, to start a project, and post the work. Or paste an invite link someone sent you, or the id of a discoverable project, and press Start. The network gives your machine work from then on.

Prefer the terminal? Every step has a command: baton --help, and the README.
